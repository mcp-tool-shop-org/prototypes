# v0.8.0 — Pedagogy Without Hierarchy

## What Teaching Means Here

Teaching in Dev-Op-Typer means exposing structure, not directing behavior. The app provides context and alternatives alongside practice — never curricula, grades, prerequisites, or sequencing. Users learn through exposure, not instruction.

Two new optional fields on snippets carry teaching content:

- **Scaffold**: progressive layers of context, from shallow hint to deeper understanding
- **Variants**: alternative implementations that demonstrate breadth without ranking

Both travel in `.ldtpack` bundles. Both are anonymous. Both are display-only. Neither affects how the app selects snippets, adjusts difficulty, or calculates ratings.

## What This Is NOT

- NOT a learning management system (LMS)
- NOT a curriculum with prerequisites or sequencing
- NOT a grading system with pass/fail or mastery levels
- NOT a mentorship platform with teacher/student roles
- NOT a recommendation engine ("you should learn X next")
- NOT a progress tracker for pedagogical goals

## Design Principles

### 1. Depth Without Hierarchy

Scaffolds provide progressive context: a shallow hint at layer 0, deeper understanding at layer 1+. The user controls depth. The app never recommends a depth level, never tracks which layers a user reads, and never uses scaffold depth as a signal for anything.

A beginner who reads only the shallow hint gets value. An expert who reads all layers gets value. Neither is pressured toward the other.

### 2. Breadth Without Ranking

Variants show alternative implementations as structural equals. There is no "preferred" variant, no "best practice" label, no ordering by quality. Multiple valid approaches coexist without judgment.

The app never suggests one variant over another. There is no metadata that implies preference (no stars, no votes, no "recommended" labels).

### 3. Teaching Through Exposure

All teaching content is observational, not prescriptive:
- "This pattern uses a list comprehension" (observational)
- "You should use a list comprehension" (prescriptive — rejected)
- "List comprehensions evolved from set-builder notation" (contextual)
- "Always prefer list comprehensions over loops" (directive — rejected)

### 4. Solo Use Remains First-Class

A snippet with no Scaffold and no Variants behaves identically to v0.7.0. Teaching content is purely additive. Removing it changes nothing about the practice experience.

### 5. Anonymous by Design

Teaching content carries no author, no source, no attribution. There is no TeachingLevel, no Prerequisite, no ScaffoldAuthor field. Reflection tests enforce this constraint at the type level.

### 6. Detachable Layers

Teaching features can be toggled off independently:
- ShowScaffolds: hides all scaffold context
- ShowVariants: hides all alternative implementations

Disabling has zero penalty. The app does not remind users that teaching content exists, suggest they re-enable it, or treat disabled state as unusual.
