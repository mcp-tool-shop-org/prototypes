# Weakness Detection — v0.9.0 Phase 3

## Purpose

The weakness detection system adds time-aware skill tracking alongside the existing cumulative MistakeProfile. While MistakeProfile remembers everything forever (good for lifetime stats), the rolling WeaknessWindow lets recent improvements naturally reduce weakness scores without any explicit "I fixed it" action.

## Architecture

### WeaknessWindow (Model)

Rolling decay window stored in `PersistedState`. Records `MistakeEvent(Category, Timestamp)` entries with automatic pruning:

- **MaxEvents**: 500 (prevents unbounded growth)
- **MaxAgeDays**: 30 (old mistakes fade naturally)
- **Recency decay**: events in the recent half of the window count at full weight (1.0×); older events count at 0.5×

This means a user who struggled with braces last week but stopped making brace errors will see that weakness naturally fade from their profile.

### WeaknessDetector (Service)

Bridges WeaknessWindow with SnippetSelector's existing weakness boost mechanism:

- **Primary**: reads from WeaknessWindow (recency-aware)
- **Fallback**: reads from MistakeProfile when the window is empty (cold start)
- **DescribeWeaknesses()**: produces human-readable weakness context for planner reasons
- **GetWeaknessScores()**: produces structured entries for UI display

### SkillSignal + SkillSignalBuilder

Aggregates all skill-related data into a single display snapshot:

- Comfort zone status
- Session plan context
- Rolling weakness entries with labels and scores
- Yo-yo / manual lock state
- Human-readable summary

## Integration Points

### SessionPlanner Enrichment

`PlanNext()` accepts an optional `WeaknessWindow` parameter. When provided, the plan reason string is enriched with weakness context:

- "Practicing at D4" → "Practicing at D4 — targeting braces weakness"
- "Reinforcing D3 mastery" → "Reinforcing D3 mastery — targeting operators and quotes weaknesses"

**Critical invariant**: weakness context only enriches the reason string. It never changes the target difficulty, mix category, or snippet selection weights. This is proven by 19 invariant tests.

### MainViewModel

- Records `MistakeEvent` entries to `WeaknessWindow` alongside existing `MistakeProfile` recording
- Passes `WeaknessWindow` to `SessionPlanner.PlanNext()` for reason enrichment
- Calls `SkillSignalBuilder.Build()` to generate UI skill signals
- Displays rolling weakness scores and summary in the sidebar

### Sidebar Display

Below the existing "Weaknesses" section (cumulative lifetime data), the rolling weakness signal shows:

- Italic summary text (e.g., "Comfort D4 — braces needs work")
- Monospace weakness score entries with intensity values

## Display-Only Guarantees

The entire weakness detection system is display-only:

| Component | Never affects |
|-----------|--------------|
| WeaknessWindow | Rating, XP, difficulty, selection |
| WeaknessDetector | MistakeProfile (read-only), WeaknessWindow (read-only) |
| SkillSignal | Any mutable state (init-only properties) |
| SessionPlanner weakness context | Target difficulty, mix category |
