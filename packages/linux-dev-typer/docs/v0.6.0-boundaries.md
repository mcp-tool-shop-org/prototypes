# What Dev-Op-Typer Will Never Be

This document defines the permanent boundaries of the project. These are not "not yet" features — they are deliberate non-goals that protect the tool's identity.

## Non-Goals

### No Cloud, No Accounts
- No user accounts, no sign-up, no authentication
- No cloud sync, no remote storage, no telemetry
- Everything lives in `~/.config/linux-dev-typer/` and nowhere else
- Portability is solved with `.ldtpack` files, not with servers

### No Social Features
- No leaderboards, no multiplayer, no sharing
- No "compare with friends" or community rankings
- Practice is private. Progress is personal.

### No Gamification Pressure
- No streaks, no daily goals, no FOMO mechanics
- No notifications, no reminders, no "you missed a day"
- XP and rating exist for self-tracking, not for competition
- The app never makes you feel bad for not practicing

### No AI Code Generation
- Snippets are hand-authored or user-authored
- No LLM-generated content, no procedural snippet creation
- The snippet format is stable, human-readable JSON

### No Plugin System
- User packs and profiles are the extension surface
- No scripting, no hooks, no third-party code execution
- Extensions are data (JSON), never code

### No IDE Integration
- This is a standalone practice tool, not an IDE plugin
- No VS Code extension, no JetBrains plugin
- The app runs independently and stays simple

### No Lesson Plans or Curricula
- No guided courses, no structured learning paths
- The adaptive difficulty system is the curriculum
- Users choose what to practice; the app adjusts to match

### No Real-Time Typing Analysis
- No heatmaps, no finger-tracking, no keystroke analytics beyond what exists
- Mistake profiles track *what* you mistype, not *how* you type
- No ergonomic advice, no typing form feedback

## Why Boundaries Matter

Every feature added is a feature that must be maintained, tested, and explained. Boundaries keep the codebase small enough for one person to understand completely, and keep the user experience focused on what matters: practicing code typing in a calm, private, pressure-free environment.

These boundaries are load-bearing. Removing them would change what the tool is.
