# Extensibility Philosophy

## Core Principle

Extensions augment. They never override.

User-authored content (snippet packs, practice profiles, portable bundles) adds to the system without replacing or breaking anything that already works. A fresh install with no user content behaves identically to the previous version.

## What Users Can Extend

### Snippet Packs
- Add new languages by dropping `.json` files into the packs directory
- Add more snippets to existing languages (user snippets merge with built-in ones)
- Enable/disable packs independently without deleting files

### Practice Profiles
- Create named parameter sets that tune engine behavior (XP rates, comfort thresholds, trend sensitivity)
- The "Default" profile is hardcoded and cannot be edited or deleted
- Switch profiles at any time; changes take effect on the next session

### Portable Bundles
- Export user packs and profiles as a single `.ldtpack` file
- Import on another machine to replicate your setup
- Only user-authored content travels; state and history stay local

## What Extensions Cannot Do

- Override built-in snippet packs (they always load)
- Modify the Default practice profile
- Export or import session history or ratings
- Bypass validation (invalid snippets are skipped, extreme profile values are clamped)
- Affect other users' installations

## Design Boundaries

These are intentional constraints, not missing features:

- **No cloud sync.** Everything is local files.
- **No accounts.** Your identity is your filesystem.
- **No multiplayer.** Practice is personal.
- **No plugin API.** Extensions are data files, not executable code.
- **No telemetry.** Nothing phones home.

## Stability Guarantees

- Built-in snippet packs are never removed or altered by user actions
- The Default profile always matches the hardcoded engine constants
- Schema migrations preserve all existing data
- Removing the packs directory is safe (the app degrades gracefully to built-in only)
