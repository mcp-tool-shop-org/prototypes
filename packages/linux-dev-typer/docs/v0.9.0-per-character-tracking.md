# Per-Character Tracking — v0.9.0 Phase 5

## Purpose

Phase 5 connects the MistakeHeatmap and WeaknessTracker systems into the live session flow, giving users per-character weakness visibility with trajectory context. While Phase 3's WeaknessWindow operates at the symbol category level (braces, quotes, operators), this phase tracks individual characters ('{', '(', ';') with confusion pairs and improvement trajectories.

## Architecture

### MistakeHeatmap (Model)

Per-character hit/miss frequency tracker stored in PersistedState:

- **RecordHit(char)**: marks a correctly typed character
- **RecordMiss(char, char?)**: marks an incorrectly typed character with optional confusion pair
- **GetErrorRate(char)**: all-time error rate (0.0 = perfect, 1.0 = always wrong)
- **GetRecentErrorRate(char)**: windowed error rate from last N attempts
- **GetWeakest(count, minAttempts)**: top N weakest characters by error rate
- **GetWeakestCategories(minAttempts)**: aggregated by SymbolCategoryKind
- **GetWeakCharSet(threshold, minAttempts)**: flat set for backward compat

Rolling window via `RecentAttempts` (list of bool: true=hit, false=miss), capped at `DefaultWindowSize * 2`.

### WeaknessTracker (Service)

Trajectory analysis comparing current heatmap state with historical snapshots:

- **GetReport(language, heatmap, snapshots)**: enriched weakness report with trajectory
- **GetPriorityWeakness(report)**: single most important weakness to focus on
- **MaybeSnapshot(language, heatmap, snapshots)**: captures daily snapshot (at most once per day per language, capped at 90)

Trajectories:
- **Improving**: error rate decreasing from previous snapshot
- **Worsening**: error rate increasing
- **Steady**: within threshold of previous
- **New**: no historical comparison available

### WeaknessSnapshot (Model)

Point-in-time capture of top weak characters for a language. Stored in `PersistedState.WeaknessSnapshots`. Fields: Language, CapturedAt, TopWeaknesses (list of char + error rate + attempts).

## Integration

### Session Recording (MainViewModel)

After each session, the completion flow:
1. Records category-level mistakes to MistakeProfile (existing)
2. Records decay events to WeaknessWindow (existing)
3. **NEW**: Records per-character hits/misses to MistakeHeatmap
4. **NEW**: Calls WeaknessTracker.MaybeSnapshot() for trajectory tracking

`RecordHeatmapData()` iterates the snippet code, matching positions against `result.Mistakes` to classify each character as hit or miss.

## Schema

v10 → v11 migration adds:
- `MistakeHeatmap` (defaults to empty)
- `WeaknessSnapshots` (defaults to empty list)

Both are initialized by the migrator; no data loss for existing users.

## Invariants

12 invariant tests prove:
- No engine (RatingEngine, XpEngine, DifficultyMemory, SnippetSelector) reads MistakeHeatmap
- No engine reads WeaknessTracker or WeaknessReport
- SessionPlanner never reads WeaknessSnapshot
- GetReport() never mutates heatmap or snapshot inputs
- Selection is identical with and without heatmap data (50-pick comparison)

## Performance

5 performance tests:
- 100K heatmap records under 1s
- 10K GetWeakest queries under 500ms
- 5K tracker reports under 2s
- 10K MaybeSnapshot calls under 1s (idempotent — one per day)
- 1K full pipeline sessions under 3s
