# v1.0.0 Signals Trust Model

## What Signals Are

Signals are observations about your typing patterns. They come from two sources:

- **MistakeHeatmap**: Per-character hit/miss tracking. Records which characters you mistype most often, how frequently, and what you type instead (confusion pairs).
- **MistakeProfile**: Per-category weakness tracking. Groups characters into symbol categories (parentheses, braces, operators, etc.) and tracks error rates per category.

Both are populated passively during every typing session. Neither requires user action.

## What Signals Are Not

Signals are **not prescriptions**. They don't tell you what to practice, don't assign homework, and don't judge your skill level. They're a mirror, not a teacher.

Signals never affect:
- **Rating calculation** (RatingEngine reads accuracy + WPM, never signal data)
- **XP calculation** (XpEngine reads session results, never signal data)
- **Difficulty progression** (DifficultyMemory reads results, never signal data)
- **Session results** (results are computed from keystrokes, not from signal state)

This is enforced by reflection-based invariant tests that verify these engine methods never accept signal types as parameters.

## Guided Mode

Guided Mode is the single user-facing toggle that allows signals to influence practice behavior. It is **off by default** and must be explicitly enabled.

### What Changes When Guided Mode Is On

With Guided Mode enabled, snippet **selection within the chosen difficulty band** prefers snippets that exercise your weak spots:

1. **HeatmapBias** (+0 to +3 weight): Counts distinct weak characters (error rate >= 15%, min 5 attempts) present in the snippet code. Each distinct weak character found adds +1 to the snippet's selection weight.

2. **HeatmapCategoryBias** (+0 to +3 weight): Counts distinct weak symbol categories present in the snippet code. Requires at least 2 weak categories to activate (diversity guard). Each category found adds +1 weight.

Both biases are **additive weight adjustments** on top of the existing difficulty-match weight (3 for exact match, 2 for off-by-one, 1 for further). They **never change the difficulty band**. A snippet at D4 stays at D4 regardless of bias.

### What Does Not Change

- The difficulty window (which bands are eligible) is unchanged
- The 50/30/20 Target/Review/Stretch mix is unchanged
- The yo-yo stabilizer is unchanged
- The manual difficulty lock overrides everything, unchanged
- Rating, XP, and difficulty progression remain signal-free

### Determinism Guarantee

With Guided Mode **off**, the planner output is identical to v0.9 behavior. Same seed, same inputs, same outputs. This is verified by invariant tests that compare v0.9 picks (no heatmap, no policy) against v1.0 picks (heatmap present but policy off).

## SignalPolicy Architecture

```
SignalPolicy
  GuidedMode: bool (master switch, default: false)
  SignalsAffectSelection: bool (default: false)
  SignalsAffectDifficulty: bool (reserved, always false)
  SignalsAffectXP: bool (reserved, always false)

Effective* properties require both master + sub-flag:
  EffectiveSelectionBias = GuidedMode && SignalsAffectSelection
  EffectiveDifficultyInfluence = GuidedMode && SignalsAffectDifficulty
  EffectiveXPInfluence = GuidedMode && SignalsAffectXP
```

When a user enables Guided Mode via the UI toggle, `EnableGuidedMode()` sets `GuidedMode = true` and `SignalsAffectSelection = true`. The difficulty and XP flags remain false (reserved for future use, if ever).

## Micro-Drills

Micro-drills are 5-item focused practice sessions targeting the top weakness category. They combine:

- **Focus category** from heatmap (preferred) or MistakeProfile (fallback)
- **FocusBoost** (+5 weight) on the target category in SnippetSelector
- **Existing session planner** for difficulty selection

Micro-drills auto-exit after 5 completions, clearing focus mode. They don't affect any engine calculations — they're a convenience wrapper around the existing focus practice system.

## Trust Boundaries

| Component | Reads Signals? | Writes Signals? |
|-----------|---------------|-----------------|
| RatingEngine | Never | Never |
| XpEngine | Never | Never |
| DifficultyMemory | Never | Never |
| SnippetSelector | Only when EffectiveSelectionBias = true | Never |
| SessionPlanner | Passes through to SnippetSelector | Never |
| WeaknessTracker | Reads heatmap (read-only) | Never mutates |
| TypingSession | Never | Produces keystrokes that feed heatmap |

The trust boundary is enforced by:
- Reflection tests (engines never accept signal types)
- Behavioral tests (policy-off produces identical output to no-signal)
- Cap tests (bias capped at +3, never changes band)
- Determinism tests (same seed = same output)
