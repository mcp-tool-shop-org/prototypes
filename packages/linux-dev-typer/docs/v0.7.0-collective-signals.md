# v0.7.0 — Collective Signals: Ethical Boundaries

## What CommunityDifficulty Is

CommunityDifficulty is an optional `double?` field on Snippet. It represents what others found the actual difficulty of a snippet to be — a collective observation from shared `.ldtpack` bundles.

It appears as a single number on the completion card: `Community: 4.2`.

## What CommunityDifficulty Is NOT

CommunityDifficulty is **never** used by any engine or selection algorithm:

- **Not read by SnippetSelector** — snippet selection uses the authored `Difficulty` field only
- **Not read by DifficultyMemory** — comfort zone tracking uses session results only
- **Not read by RatingEngine** — Elo adjustment uses authored `Difficulty` only
- **Not read by any weighting algorithm** — adaptive selection ignores it entirely

Multiple firewall tests enforce this isolation.

## Ethical Boundaries

### No Norm-Setting
CommunityDifficulty is informational, not normative. It doesn't say "this should be difficulty 4.2" — it says "others observed this at 4.2." The distinction matters: one sets expectations, the other shares experience.

### No Hidden Adaptation
The app never silently adjusts behavior based on community data. If CommunityDifficulty were used to re-weight snippets, users would unknowingly have their practice shaped by others' preferences. That's the opposite of solo-first design.

### No Comparison
CommunityDifficulty never appears alongside a user's personal difficulty assessment in a way that suggests one is "right" and the other "wrong." Both are observations. Both are valid.

### Display-Only, Toggleable
The signal can be turned off independently from the sidebar (ShowCommunitySignals toggle). Disabling it has zero effect on practice behavior. No penalty, no nagging, no reminder to turn it back on.

## Why This Matters

When you give users collective data about difficulty, you risk creating implicit pressure: "everyone else found this easy, so I should too." Dev-Op-Typer avoids this by:

1. Making the signal subtle (muted text, monospace, behind Details toggle)
2. Never comparing it to the user's performance
3. Never using it to adjust the user's experience
4. Making it independently disableable
5. Never labeling it as "correct" or "expected"
