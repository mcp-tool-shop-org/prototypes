# v0.8.1 — Content System Integration

## Overview

v0.8.1 integrates the `DevOpTyper.Content` shared library (v1.0.0) into linux-dev-typer, enabling users to paste code or import files/folders as new typing practice content. The content system runs alongside the existing snippet pipeline — it adds new content sources without replacing any existing behavior.

## Architecture

### Bridge Pattern

The integration uses a **bridge pattern**: `CodeItem` (from the content library) is converted to `Snippet` (the existing typing engine model) at query time. This keeps all 330 existing tests green while unlocking new content flows.

```
DevOpTyper.Content pipeline:
  IContentSource → DefaultExtractor → Normalizer → MetricCalculator → ContentId → CodeItem

Bridge:
  CodeItem → Snippet (Difficulty=3 default, empty Topics/Explain)

Existing pipeline (unchanged):
  IAssetProvider → List<Snippet> → SnippetSelector.Pick()
```

### Content Sources

| Source | How content enters | Storage |
|--------|-------------------|---------|
| Built-in | `assets/snippets/*.json` via `LocalAssetProvider` | Bundled with app |
| User packs | `~/.config/linux-dev-typer/packs/*.json` via `UserPackProvider` | User-managed files |
| **Pasted code** | Sidebar "Paste Code" flow → `ContentIntegrationService.PasteCode()` | `library.index.json` |
| **Imported files** | Sidebar "Import File" flow → `ContentIntegrationService.ImportFileAsync()` | `library.index.json` |
| **Imported folders** | Sidebar "Import Folder" flow → `ContentIntegrationService.ImportFolderAsync()` | `library.index.json` |

### Snippet Selection

The typing engine consumes snippets from two providers:
1. `CompositeAssetProvider` — built-in + user pack snippets (full metadata: Difficulty, Topics, Explain, etc.)
2. `ContentAssetProvider` — content library items converted to Snippets (Difficulty=3 default)

Both are merged in `MainViewModel.NewTest()` before calling `SnippetSelector.Pick()`.

### Deduplication

Content-addressed IDs (SHA-256 of `language + "\n" + normalizedCode`, first 16 bytes hex) prevent duplicate entries. Pasting the same code twice or importing the same file again produces no new items.

## Storage

| Artifact | Path |
|----------|------|
| Content library index | `{ConfigDirectory}/library.index.json` |
| State file | `{ConfigDirectory}/state.json` (unchanged) |
| Built-in packs | `assets/snippets/` (unchanged) |
| User packs | `{ConfigDirectory}/packs/` (unchanged) |

Where `ConfigDirectory` = `~/.config/linux-dev-typer/` (Linux) or `%APPDATA%/linux-dev-typer/` (Windows).

## Resilience

- Missing `library.index.json` → empty library, no crash
- Corrupt JSON → empty library, no crash
- Empty index → app boots normally, zero content items
- Import failure (unreadable file) → skipped silently, other files continue
- Files > 2MB → skipped during folder import

## Key Design Decisions

1. **Bridge, not replace**: CodeItem → Snippet conversion preserves all existing engine behavior
2. **Difficulty=3 default**: User-pasted/imported code has no authored difficulty; defaults to medium
3. **Manual import only**: No file watchers — import is a deliberate user action
4. **No schema bump**: Content index is a separate file; `state.json` schema stays at v10
5. **Content pipeline in App layer**: `ContentIntegrationService` lives in App, not Core — Core stays dependency-free
