# Explanation Transparency — v0.9.0 Phase 4

## Purpose

Phase 4 surfaces the internal decision-making of the session planner and weakness detector so users understand *why* each snippet was chosen. Every selection factor is visible on the completion card; no hidden logic, no black box.

## Architecture

### SelectionExplanation (Model)

Structured explanation of a snippet selection. Init-only properties, display-only — never fed back into any engine.

Fields:
- **PrimaryReason**: the plan's raw reason string
- **Factors**: 2-5 human-readable lines explaining contributing factors
- **WeaknessInfluenced**: whether weakness boost affected this pick
- **FocusInfluenced**: whether focus mode affected this pick
- **Category**: the mix category (Target / Review / Stretch)
- **TargetDifficulty / ActualDifficulty**: what was aimed for vs what was available

### ExplanationBuilder (Service)

Constructs a `SelectionExplanation` from the current selection context:

1. **Mix category factor** — "Target session — at your working level" / "Review session — reinforcing familiar patterns" / "Stretch session — gentle push toward growth"
2. **Difficulty factor** — "Difficulty D4 (exact match)" or "Difficulty D3 (targeted D4)"
3. **Weakness boost factor** (optional) — "Exercises weak spot: braces" when the snippet contains characters matching the user's rolling weaknesses
4. **Focus mode factor** (optional) — "Focus practice: operators" when focus mode is active
5. **Comfort zone factor** (optional) — "Comfort zone: D4" when calibrated

Inputs are read-only: the builder never modifies the plan, snippet, weakness set, or focus category.

### ReasonFormatter (Service)

Formats a `SessionPlan` into a human-readable pick reason with a category icon:

- Target: "🎯 Target: D4 — at your comfort zone"
- Review: "🔄 Review: D2 — reinforcing familiar patterns"
- Stretch: "💪 Stretch: D6 — pushing toward growth"

Falls back to the raw plan reason when no comfort zone is set.

## UI Display

### Completion Card

After completing a snippet, the "Details" toggle reveals a "Why this snippet" section:

```
Why this snippet
🎯 Target: D4 — at your comfort zone
  + Target session — at your working level
  + Difficulty D4 (exact match)
  + Exercises weak spot: braces
  + Comfort zone: D4
```

Each factor is prefixed with `+` in muted styling. The section is only visible when factors exist.

### Sidebar Skill Signals

The sidebar shows a rolling skill summary below the weakness section:

- Italic summary text (e.g., "Comfort D4 — braces needs work")
- Monospace weakness scores (e.g., "  braces (3.5)")

Updated on startup and after each session.

## Accessibility

All explanation and signal UI elements have `AutomationProperties.Name`:
- "Selection explanation header"
- "Selection reason"
- "Selection factors list"
- "Skill summary"
- "Rolling weakness scores"

## Invariants

12 invariant tests enforce:

1. **Init-only properties** — SelectionExplanation fields use `{ get; init; }`, verified via `IsExternalInit` modreq on setter return parameter
2. **Inputs never modified** — ExplanationBuilder.Build() doesn't mutate the plan, snippet, or weakness set
3. **Engines never read explanation** — RatingEngine, XpEngine, DifficultyMemory, SnippetSelector have no dependency on SelectionExplanation
4. **Format consistency** — ReasonFormatter produces non-empty, non-null strings for all categories
